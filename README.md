English | Skills for coding agents that drive the **local-only** Flisk CLI.

### Stop letting agents guess your local infrastructure.

Coding agents are excellent at writing application logic and terrible at keeping Dockerfiles, Tiltfiles, nginx configs and port assignments consistent. Every hallucinated config burns tokens and developer time.

**Flisk Skills** give agents verified, portable procedures for the Flisk `service.json` contract. Agents run `flisk doctor`, scaffold resources, start stacks with `flisk up`, and diagnose failures using the same commands a human would — without inventing Kubernetes or Compose.

### ⚡ Install in seconds

```bash
curl -fsSL https://flisk.sh/install.sh | sh                                              # 1. CLI
npx skills add flisk-sh/flisk-skills                                                                 # 2. skills
curl -fsSL https://raw.githubusercontent.com/flisk-sh/flisk-skills/main/install.sh | sh -s -- --agent codex   # 2 (alt)
curl -fsSL https://raw.githubusercontent.com/flisk-sh/flisk-skills/main/rules/AGENTS.landscape.md -o AGENTS.md  # 3. rules template (optional)
```

`install.sh` flags: `--agent claude|codex|opencode|cursor|agents`, `--global`, `--project` (default). It only creates symlinks (never copies markdown, never uses `sudo`).

## Why Flisk Skills?

- **One canonical copy.** Skills live under `skills/`; the installer and plugin only symlink them.
- **Agent Skills spec.** Each skill has YAML frontmatter (`name`, `description`) that agents use as a trigger.
- **Verified workflows.** Procedures come from real sessions on large stacks (including 100+ service ERP measurements).
- **Local only.** Every skill reinforces that Flisk is Docker + Tilt on your machine, not a deploy tool.

## Skills

| Skill | Use |
|---|---|
| `flisk-doctor` | Check or repair the machine and project before `flisk up` (`--all`, `--json`, `--fix`). |
| `flisk-troubleshoot` | Diagnose a stack that started and then failed: red Tilt resources, crash loops, unhealthy services, an overloaded machine. |
| `flisk-scaffold` | Start a project (blank or from a starter or example) and add new services with `flisk resource`. |
| `flisk-build-runtimes` | Pick the language or framework of a new service (Bun, Python, Go, Rust, Node; React, Vue, Next.js and more). |
| `flisk-frontend` | Add a web app to a stack and work with its generated nginx, Vite and API client files. |
| `flisk-agents` | Build and operate AI agent resources: the session contract, checkpoints and `flisk agent sessions`. |
| `flisk-demo-bubbles` | Hand out a personalised demo.flisk.sh stack for a person: link, JSON API or the `make_demo` MCP tool. |
| `flisk-unfollowers` | Who unfollowed an X account in a 10m, 1h or 1d window, from stored follower lists (`get_unfollowers` MCP tool). |
| `flisk-byo` | Bring an existing Dockerfile, image or one-shot job into a stack as a bring-your-own resource. |
| `flisk-import-compose` | Import a root `docker-compose.yml` with `flisk import`. |
| `flisk-import-procfile` | Turn Procfile processes into bring-your-own resources. |
| `flisk-service-json` | Edit and validate an existing service's `service.json`. |
| `flisk-generated-files` | Who owns `.autogenerated/`, drift checks and regeneration. |
| `flisk-databases` | Give a service a database and migrations (Prisma, Drizzle, Atlas, Dbmate and others). |
| `flisk-data` | Reset, seed, snapshot and restore local Postgres data. |
| `flisk-secrets` | `params`, secrets, the project `.env` and `flisk up --env-file`. |
| `flisk-ports` | Routed URLs (`flisk networks`), Traefik, host ports and their overrides. |
| `flisk-dry-run` | Preview `flisk up`, `down`, `import`, `doctor --fix` and `upgrade --all` without changing anything. |
| `flisk-ui` | The interactive terminal dashboard (`flisk ui`). |
| `flisk-upgrade` | Upgrade the CLI and keep a team on `minFliskVersion`. |
| `flisk-layout` | Where the project lives when services span several repos or teams. |
| `flisk-starlark-perf` | Make discovery, Tiltfile evaluation and golden builds faster. |
| `flisk-benchmark` | Measure memory per service, start times and how many services fit on a machine. |
| `flisk-helm` | Keep Helm, Argo CD, Flux or Kustomize for production next to Flisk locally. |
| `flisk-deploy-aws` | Ship a working stack to AWS (ECS/Fargate, EKS, App Runner, Lambda, EC2). |
| `flisk-deploy-azure` | Ship a working stack to Azure (Container Apps, AKS, App Service, Functions). |
| `flisk-deploy-gcp` | Ship a working stack to Google Cloud (Cloud Run, GKE, App Engine, Compute Engine). |
| `flisk-deploy-digitalocean` | Ship a working stack to DigitalOcean (App Platform, Droplets, Kubernetes). |
| `flisk-deploy-cloudflare` | Ship a frontend or compatible service to Cloudflare (Pages, Workers). |
| `flisk-deploy-vercel` | Ship a frontend or serverless functions to Vercel. |
| `flisk-deploy-fly` | Ship a working stack to Fly.io. |
| `flisk-deploy-heroku` | Ship a working stack to Heroku. |
| `flisk-deploy-railway` | Ship a working stack to Railway. |
| `flisk-deploy-render` | Ship a working stack to Render. |
| `flisk-contributing` | Contribute to the flisk CLI repository itself. |
| `layer-autoresearch` | Contributor experiment loop that optimises the L1-L4 Docker layers (keep/discard). |

`flisk project` also writes a smaller set of project skills (`flisk-build`, `flisk-resource`, `flisk-up`, `flisk-status` and the recipes) into every new project; those live in [flisk](https://github.com/flisk-sh/flisk/tree/main/.claude/skills).

The AI review buttons skill that used to be here as `flisk-pr-review-buttons` is not Flisk-specific; use [`gh-pr-review-buttons`](https://github.com/odykyi/gh-skills/tree/main/skills/gh-pr-review-buttons) from odykyi/gh-skills.

More skills are welcome — see [SPEC.md](SPEC.md) and open a PR. Each `description` must say when to use the skill and how it differs from its neighbours, because agents pick a skill from that line alone.

## Repository guidance

- [`rules/AGENTS.landscape.md`](rules/AGENTS.landscape.md) is a short baseline for Flisk project, example and starter repositories.
- [`rules/AGENTS.cli-core.md`](rules/AGENTS.cli-core.md) applies only to contributors working in `flisk`.

Copy the applicable template into a repository as its root `AGENTS.md`, then add only rules specific to that repository.

## Updating skills

Edit `skills/` only; the plugin and `.agents/skills/` are symlinks. Review a skill here first. Product-specific command behavior should be checked against [`flisk`](https://github.com/flisk-sh/flisk) before publishing. Keep any mirror in the CLI repository synchronized from this source.

## For agents and LLMs

- [`llms.txt`](llms.txt) indexes every skill and rules template with raw URLs.
- [`AGENTS.md`](AGENTS.md) is the short instruction file for tools that don't load skills.
- The Flisk site publishes its own index at <https://flisk.sh/llms.txt> and a guide at <https://flisk.sh/docs/agents/>.

See [SPEC.md](SPEC.md) for the design.
