# Flisk (local development)

- Flisk is local only. It runs a Docker + Tilt inner loop and does not deploy.
- Run `flisk doctor`, then `flisk up`, from the project root.
- Do not invent Kubernetes manifests or Docker Compose files.

## Skills

Each skill is a folder under `skills/` with a `SKILL.md`:

- `skills/flisk-doctor/SKILL.md`: check or repair the machine and project before `flisk up` (`--all`, `--json`, `--fix`).
- `skills/flisk-troubleshoot/SKILL.md`: diagnose a stack that started and then failed: red Tilt resources, crash loops, unhealthy services, an overloaded machine.
- `skills/flisk-scaffold/SKILL.md`: start a project (blank or from a starter or example) and add new services with `flisk resource`.
- `skills/flisk-build-runtimes/SKILL.md`: pick the language or framework of a new service (Bun, Python, Go, Rust, Node; React, Vue, Next.js and more).
- `skills/flisk-frontend/SKILL.md`: add a web app to a stack and work with its generated nginx, Vite and API client files.
- `skills/flisk-agents/SKILL.md`: build and operate AI agent resources: the session contract, checkpoints and `flisk agent sessions`.
- `skills/flisk-byo/SKILL.md`: bring an existing Dockerfile, image or one-shot job into a stack as a bring-your-own resource.
- `skills/flisk-import-compose/SKILL.md`: import a root `docker-compose.yml` with `flisk import`.
- `skills/flisk-import-procfile/SKILL.md`: turn Procfile processes into bring-your-own resources.
- `skills/flisk-service-json/SKILL.md`: edit and validate an existing service's `service.json`.
- `skills/flisk-generated-files/SKILL.md`: who owns `.autogenerated/`, drift checks and regeneration.
- `skills/flisk-databases/SKILL.md`: give a service a database and migrations (Prisma, Drizzle, Atlas, Dbmate and others).
- `skills/flisk-data/SKILL.md`: reset, seed, snapshot and restore local Postgres data.
- `skills/flisk-secrets/SKILL.md`: `params`, secrets, the project `.env` and `flisk up --env-file`.
- `skills/flisk-ports/SKILL.md`: routed URLs (`flisk networks`), Traefik, host ports and their overrides.
- `skills/flisk-dry-run/SKILL.md`: preview `flisk up`, `down`, `import`, `doctor --fix` and `upgrade --all` without changing anything.
- `skills/flisk-ui/SKILL.md`: the interactive terminal dashboard (`flisk ui`).
- `skills/flisk-upgrade/SKILL.md`: upgrade the CLI and keep a team on `minFliskVersion`.
- `skills/flisk-layout/SKILL.md`: where the project lives when services span several repos or teams.
- `skills/flisk-starlark-perf/SKILL.md`: make discovery, Tiltfile evaluation and golden builds faster.
- `skills/flisk-benchmark/SKILL.md`: measure memory per service, start times and how many services fit on a machine.
- `skills/flisk-helm/SKILL.md`: keep Helm, Argo CD, Flux or Kustomize for production next to Flisk locally.
- `skills/flisk-deploy-aws/SKILL.md`: ship a working stack to AWS (ECS/Fargate, EKS, App Runner, Lambda, EC2).
- `skills/flisk-deploy-azure/SKILL.md`: ship a working stack to Azure (Container Apps, AKS, App Service, Functions).
- `skills/flisk-deploy-gcp/SKILL.md`: ship a working stack to Google Cloud (Cloud Run, GKE, App Engine, Compute Engine).
- `skills/flisk-deploy-digitalocean/SKILL.md`: ship a working stack to DigitalOcean (App Platform, Droplets, Kubernetes).
- `skills/flisk-deploy-cloudflare/SKILL.md`: ship a frontend or compatible service to Cloudflare (Pages, Workers).
- `skills/flisk-deploy-vercel/SKILL.md`: ship a frontend or serverless functions to Vercel.
- `skills/flisk-deploy-fly/SKILL.md`: ship a working stack to Fly.io.
- `skills/flisk-deploy-heroku/SKILL.md`: ship a working stack to Heroku.
- `skills/flisk-deploy-railway/SKILL.md`: ship a working stack to Railway.
- `skills/flisk-deploy-render/SKILL.md`: ship a working stack to Render.
- `skills/flisk-contributing/SKILL.md`: contribute to the flisk CLI repository itself.
- `skills/flisk-demo-bubbles/SKILL.md`: hand out a personalised demo.flisk.sh stack for a person ("Grok bubbles"): link, JSON API or the `make_demo` MCP tool.
- `skills/flisk-unfollowers/SKILL.md`: who unfollowed an X account in a 10m / 1h / 1d window, from stored follower lists (`get_unfollowers` MCP tool).
- `skills/layer-autoresearch/SKILL.md`: contributor experiment loop that optimises the L1-L4 Docker layers (keep/discard).

If your tool does not load skills automatically, read the relevant `SKILL.md` directly.
