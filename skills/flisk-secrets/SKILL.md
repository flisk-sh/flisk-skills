# Environment, params and secrets

TDK projects use a project-level .env and service-specific generated env files.

## Workflow

1. Keep secrets out of git. Use the project .env (gitignored) or the documented params/secrets mechanism.
2. Generated `.env.*.autogenerated` files are written by the CLI; edit the source service.json or project config instead.
3. Run `tdk doctor` after changing environment-related settings.
4. See docs on environment, params and secrets in flisk.

## Guardrails

- Never commit real secrets or license keys.
- .tdk/.project-id is local machine state; ensure it is gitignored.
- Premium features that need a key are optional and documented separately.
