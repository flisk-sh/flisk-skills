# Scaffold Flisk resources and stacks

Use the CLI to generate consistent service.json and starter code instead of hand-writing boilerplate.

## Workflow

1. From the project root, decide the stack name (e.g. `shop`, `identity`).
2. For a new project: `flisk project --yes` (or `flisk project example` to fetch a working example).
3. Scaffold a resource:
   ```bash
   flisk resource orders-api --type backend --stack shop --yes
   flisk resource storefront --type frontend --stack shop --yes
   flisk resource bot --type agent --stack shop --yes
   flisk resource tools-mcp --type mcp --stack shop --yes
   ```
4. Review the generated `service.json` and starter files under `services/<stack>/<name>/`.
5. Adjust dependencies in `service.json` if needed, then run `flisk doctor` and `flisk up <stack>`.

## Guardrails

- Prefer `--yes` for non-interactive scaffolds in agent sessions.
- Do not hand-edit `.autogenerated/` files; regenerate via the CLI.
- Check the service schema and examples in flisk before inventing new types.
- After scaffolding, always run `flisk doctor` before `flisk up`.
