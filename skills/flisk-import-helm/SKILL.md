# Flisk next to Helm

Flisk owns the local loop. Helm owns the cluster. They are not alternatives.

## Workflow

1. Keep the existing chart and values untouched.
2. For the local service, either:
   - Scaffold a matching resource with `flisk resource ... --type backend` (or frontend), or
   - Wrap the existing Dockerfile with `flisk resource ... --type bring-your-own`.
3. Run `flisk up <stack>` for local development.
4. Continue to deploy with `helm upgrade` (or Flux/Argo) using the same image.

## Mapping (conceptual only)

| Flisk | Helm / cluster |
| --- | --- |
| `appName` | release or controller identity |
| `port` | Service port |
| `healthCheckPath` | may inform probes |
| `dependsOn` | does not become chart hooks |
| Traefik `*.localhost` | not a production Ingress |

## Guardrails

- Do not copy `.autogenerated/` into a chart. It is local Docker/Tilt output.
- There is no `flisk export` to Helm. Keep values by hand.
- Flisk does not install charts, set replicas, PVCs, IRSA, or HPA.
- If `helm install` or your existing Tilt setup already works for local, you can skip Flisk.
