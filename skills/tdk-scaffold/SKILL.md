# Scaffold TDK resources and stacks

Use the CLI to generate consistent service.json and starter code instead of hand-writing boilerplate.

## Workflow

1. From the project root, decide the stack name (e.g. `shop`, `identity`).
2. For a new project: `tdk project --yes` (or `tdk project example` to fetch a working example).
3. Scaffold a resource:
   ```bash
   tdk resource orders-api --type backend --stack shop --yes
   tdk resource storefront --type frontend --stack shop --yes
   tdk resource bot --type agent --stack shop --yes
   tdk resource tools-mcp --type mcp --stack shop --yes
   ```
4. Review the generated `service.json` and starter files under `services/<stack>/<name>/`.
5. Adjust dependencies in `service.json` if needed, then run `tdk doctor` and `tdk up <stack>`.

## Guardrails

- Prefer `--yes` for non-interactive scaffolds in agent sessions.
- Do not hand-edit `.autogenerated/` files; regenerate via the CLI.
- Check the service schema and examples in tdk-cli-core before inventing new types.
- After scaffolding, always run `tdk doctor` before `tdk up`.
